# Project logo companion protocol

`ProjectLogos` reads and signs the additive `kithmoot.project-logo.v1` domain
used by the browser. Strict v1 project definitions and their existing readers
are unchanged. The caller supplies its already-verified current directory.

The owner signs kind 30078 with `d=logo:<project>` and the companion label.
The body binds the project, current directory authority, bounded version,
request and inline still image or explicit removal. Images use the existing
16 KiB/256-pixel private format. Bodies are limited to 24 KiB and encrypted
envelopes to 50,000 characters. NIP-44 wrappers carry only the recipient and
companion label. Temporary keys are erased after wrapping.

An unrelated recipient, invalid directory, altered envelope or wrong domain
never invokes decryption. Valid envelopes decrypt once across current project
candidates, then verify the inner owner, signature, time, authority and image.
Cancellation and external decryption errors remain visible to the account
adapter. Artwork cannot add membership, join a room or grant agent access.

Nine JVM tests cover image/removal round trips, permission checks before
signing, modified signatures/time/domains, membership epoch changes, invalid
envelopes before decryption, single decryption, borrowed inner owners, signer
substitutions, cancellation and numeric/size bounds. All 436 protocol tests
pass. Thirteen signed/encrypted companion fixtures generated by reviewed
browser source `70f1c8f` agree with the native reader, retaining all accepted
fields. The fixture uses repeated-byte public test keys and records the web
source revision and module hash. Regenerate only from reviewed, built web source:

```sh
node scripts/generate-project-logo-web-vectors.mjs /path/to/kithmoot full-web-source-sha
```

This is a protocol foundation. The account journal, immutable offline
envelopes/receipts, companion recovery, owner editor, contextual inheritance,
invitation/admission and originating-call UI remain to be integrated. A
complete browser-to-native user journey is still required. This change
publishes no APK and does not close G15 or physical acceptance.
