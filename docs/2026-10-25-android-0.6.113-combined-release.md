# Android 0.6.113 combined release

The owner directed one still-unpublished 0.6.113/code 136 containing the
performance work, public call relay discovery and the audio/UI changes.
The separate 0.6.114 draft was superseded and removed; its retained APK and
passing checks describe that earlier source only.

## Source review before the combined build

This is the implementing agent's review of the integration, not a fresh
independent approval. The original discovery design and independent review
findings remain in the public-relay design/review documents.

- The five relay lifecycle fixes remain intact. One selector owns ICE updates;
  manual TURN and Spry take priority; removing a public relay clears its server
  and login from a relay-only engine. Late startup/login/renewal cannot return
  after leave, and relay-only never falls back direct.
- Audio/UI handoff `5b15d426` and anchor follow-up `5c26132c` are integrated.
  The loudspeaker preference is local display state; headset priority and the
  AudioManager/Telecom hand-off remain separate from ICE server selection.
- Initial following starts only after actual loaded content establishes an
  anchor, or an explicit target/jump has been positioned. Capture samples have
  independent theme/font keys. The delayed-history regression loads sixty
  older rows and a latest marker; both capture and delayed-load checks require
  a positive scroll range and its actual end, excluding an empty-list pass.
- The jump control is below the message list. The account menu has larger
  actions and the account button uses its public kind-0 profile when enabled.
  Profile queries and pictures honour the public-profile setting; anonymous
  rooms do not display the account picture.
- Automatic profile fallbacks use Purple Pages and Primal. Both answered a
  synthetic read check on 25 October; Damus returned HTTP 503 twice and was
  omitted from that automatic list. User-configured relays and the room
  defaults primal/oxtr/ditto are preserved. This is a bounded availability
  observation, not a claim about a permanent global outage.
- Release notes are optional signed manifest data: two or three bounded,
  single-line strings. Existing clients ignore the added field. The new
  display is available after updating; its scrollable notes leave update
  actions reachable with long valid notes and large text.

## Legal-cover readback before the combined build

The integration preserves the previously reviewed publisher position and
legal reading. Discovery starts off and queries the person's read relays
without signing in. The person selects the operator; KithMoot supplies no
directory or operator list and runs no public relay or credential endpoint.
The owner's private Archy node is unchanged. Logins remain in memory and are
dropped at call end. No telemetry, content-key recipient, runtime service or
Google dependency is added by these changes.

Own-profile lookup retains the existing public-profile purpose and opt-out;
the automatic fallback change removes an unavailable recipient. Audio choice,
chat following and menu sizing are local UI state. Release-note bytes receive
the same signature verification as the APK identity. These additions do not
change the existing call-transport classification or create new legal-basis
claims. Privacy 4.5 and the shared call-transport position name Android from
0.6.113. The underlying law-note verification and unsettled readings remain
as recorded in the earlier legal-cover readback.
