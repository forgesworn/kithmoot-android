# Retirement-specific process restart acceptance

The guarded disposable-emulator driver adds four source-commit windows:
pending original, reserved before offer, offered before archive, and archive
before saved hint repair. A fixture storage wrapper delegates unchanged bytes
to real encrypted AtomicFile storage, then holds the selected source worker
live until external SIGKILL. The source keeps retirement accounting; no courier
retirement entry is invented. Design mesh-kit 7b7b652 precedes this integration
and retains the original four-window design.

Each recovery case checks the exact saved native reference/invitation digest,
public source record, current owner/peer receiver metadata and independent
courier document before activating a route or refreshing credentials. Home
checks the retired actual source despite a stale index hint. Reopen goes through
the foreground ViewModel and rendered production controls. A retained pending
reservation needs the next charged attempt; a recorded offer completes without
another automatic offer. Archives never automatically resend. Existing approved
members recover with their epoch credential, bypassing new invitation admission,
and exchange fresh chat at epoch zero. An old foreground callback refuses.
Explicit archive resend retains the original and charges the next attempt.

Preparation uses a synthetic Nearby byte endpoint, and recovery uses the same
fake BLE boundary as existing host journeys. Keystore, encrypted stores,
receiver, source/controller, ViewModel and controls are production. Neither
these fixtures nor successful emulator execution establish real radio/group
or participant-wide retirement propagation.

The shared Python driver preserves the primary failure when cleanup also
fails. Cleanup still attempts native app data/key deletion after failed
force-stop. Every existing profile is retained, and every retirement profile
requires its exact mode, live preparation PID, verified SIGKILL, exactly one
recovery case and a different PID. Old/new driver fault checks are required.

The final head requires its own four hosted jobs, all 134 ordinary checks in
43 groups (11 host/five member/one composer), all four old process-kill drivers
and these four new retirement drivers. Source/receiver/marked-courier
missing/corrupt refusal coverage remains a separate required matrix. No window
is measured merely because its source compiles or driver fault checks pass.
Replacement, terminal recovery, migration, creation/abandonment/receipts,
independent sync review and physical BLE/RF/group/airtime gates remain open.
